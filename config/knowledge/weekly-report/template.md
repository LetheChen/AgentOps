# `周报.md` 格式 Spec（v2 优化版）

周报助手 agent 的产出文件。**最终归档到 Obsidian**，所以格式必须满足：
- 人类可读（Markdown，非 JSON/YAML）
- Obsidian 可索引（frontmatter 字段完整、tag 规范、内部链接用 `[[...]]`）
- 周期可追溯（文件名 + frontmatter 双重标记周次）
- 内容可回溯（每条工作项可附原始来源段落标记 `#src:N`，N 为来源编号）

> ## 周报是结构化提炼，不是流水账堆砌
>
> 周报助手收到的是「格式杂乱的工作周报合集」（多人提交、风格不一、详略不齐），
> 产出必须做到：
>
> - **去重合并**：同一事项在不同人周报里多次出现 → 合并为一条，附多个来源编号
> - **归类不漏项**：5 大维度互斥且穷尽，模糊条目按"主要工作目的"归类
> - **量化优先**：能用数字描述的必须量化（处理量 / 影响范围 / 耗时 / 节点数）
> - **去 AI 味**：禁用「积极推进」「全力保障」「持续优化」等空话，必须有具体动作 + 对象 + 结果
> - **保留专有名词**：系统名 / 表名 / 接口名 / 工单号原样保留，不翻译不简化
> - **重要程度分级**：每条工作项必须挂 S/A/B/C 标记，便于领导 10 秒抓重点

---

## 5 维度分类边界（判定铁律，互相 MECE）

| 维度 | 判定锚点 | 典型动作动词 | 常见误归类 |
| --- | --- | --- | --- |
| **一、系统功能优化及新增** | 代码/配置变更 → 产生新功能或修复既有功能 | 开发 / 修复 / 上线 / 重构 / 调优 | 数据修复 bug → 维度三；权限矩阵调整 → 维度二 |
| **二、流程、权限、账号管理** | 流程规范/审批节点/账号生命周期 | 调整/开通/回收/配置/废止 | 单纯操作单个账号 → 维度四 |
| **三、数据处理** | 数据采集/清洗/迁移/查询/报表产出 | 清洗/迁移/归档/核对/补录 | 改配置修复数据 → 维度一 |
| **四、系统运维支撑** | 服务器/中间件/数据库/网络/磁盘/客户端 | 扩容/重启/告警处置/安装/巡检 | 业务系统使用咨询 → 维度五 |
| **五、需求沟通** | 跨部门协调/需求评审/方案对齐/客户沟通 | 沟通/对齐/评审/确认/澄清 | 仅被通知型沟通 → 不列条目 |

**判定流程**：① 这件事改了哪类资产？→ 选维度；② 涉及多个对象？→ 取主要工作目的；③ 仍模糊？→ 看「动作结果」而非「关键词」。

## 重要程度分级（S/A/B/C，铁律）

每条工作项必须挂一个等级前缀 `**[S]**` / `**[A]**` / `**[B]**` / `**[C]**`。

| 等级 | 判定标准 | 典型场景 | 量化锚点 |
| --- | --- | --- | --- |
| **S** | 影响业务连续性 / 跨部门关键阻塞解除 / 重大上线 | 核心系统故障修复、关键审批流恢复、重大上线 | 损失工时 ≥ 4h / 影响 ≥ 3 部门 / 影响 ≥ 50 用户 |
| **A** | 实质性推进 / 复杂问题闭环 / 高价值产出 | 合同台账权限扩大、跨季度数据治理、智能审核 schema 定义 | 闭环 ≥ 5 项 / 涉及 ≥ 3 表 / 涉及 ≥ 10 万行 |
| **B** | 常规推进 / 中等复杂度 / 单一流程闭环 | 流程节点调整、单个权限开通、报表补字段 | 闭环 ≤ 5 项 / 涉及 1-2 表 |
| **C** | 日常事务 / 简单答疑 / 单点操作 | 密码发放、单据作废重提、咨询一句话答复 | 操作步骤 ≤ 2 步 |

> **C 级条目合并铁律**：同类 C 级条目**不允许逐条列**，必须在维度末尾合并为汇总：`> 另处理 N 项简单咨询 / 单点操作（C 级）`。完整 10 条 C 级单条列出是失败样例。

## 归档规则

- **根目录**：`E:\Document\Weekly\`
- **文件命名**：`工作周报_YYYY-MM-DD_MM-DD.md`（如 `工作周报_2026-06-29_07-05.md`）
  - 日期范围为本周一 ~ 周日的实际日期（非 ISO 周次）
  - 生成时通过 Obsidian CLI 写入：`obsidian-cli write --vault "Document" --path "Weekly/工作周报_YYYY-MM-DD_MM-DD.md" --content "..."`
- **覆盖策略**：同一周期文件已存在时，**追加新内容到对应维度**，不整体覆盖（避免丢失人工补充）
- **若文件不存在**：创建新文件并写入完整模板
- **空周报处理**：`weekly_submissions=null` 时仍归档空周报（保留 `status: no_data` 流水记录），用于审计追溯

## Frontmatter 字段（Obsidian 元数据，必填）

```yaml
---
type: weekly_report
period: 2026-06-29_07-05                # 本周日期范围（周一_周日，与文件名一致）
period_start: 2026-06-29                 # 周一日期
period_end: 2026-07-05                   # 周日日期
generated_at: 2026-07-05T18:30:00+08:00  # 生成时间（带时区）
generated_by: weekly_report_agent
status: active  # active / no_data（空周报时改为 no_data）
item_count: 23                           # 汇总条目总数（5 维度合计）
tags:
  - 周报
  - 工作总结
  - agent-generated
  - 2026/06
  - 2026/07
  - 2026-W27
  - 系统功能优化
  - 流程权限管理
  - 数据处理
  - 系统运维支撑
  - 需求沟通
---
```

**标签设计原则**：
- `周报` / `工作总结` / `agent-generated`：固定类型标签，所有周报必带
- `2026/06` / `2026/07`：月份标签（跨月时两个都带，便于按月检索）
- `2026-W27`：ISO 周次标签（便于跨年周次对齐）
- 5 个维度标签：与正文 5 大维度一一对应，便于 Obsidian 中按维度聚合历史周报（如「查所有"系统功能优化"维度的条目」）

## agent 提炼规则（铁律 v2）

1. **去重**：同一事项在多人周报中出现 → 合并为一条，`#src:` 写多个编号（如 `#src:1,3`）
2. **归类**：严格按 5 维度 MECE 表判定，不按「提到关键词」归类
   - 修 bug → 维度一（功能优化）
   - 改配置文件修复数据 → 维度三（数据处理）
   - 调整权限矩阵修复 bug → 维度二（权限管理）
3. **重要程度分级**：每条工作必须挂 S/A/B/C，按上表判定标准
   - **C 级必须合并**：同类 C 级条目合并为汇总行（`> 另处理 N 项...`），禁止逐条列
4. **量化**：能用数字的必须用数字（处理量 / 影响范围 / 耗时 / 节点数 / 告警次数）
5. **去 AI 味**：禁用「积极推进」「全力保障」「持续优化」「有效提升」等空话
   - ❌ "积极推进审批系统优化，有效提升用户体验"
   - ✅ "完成审批中心加签逻辑修复，3 个在途审批流恢复正常"
6. **保留专有名词**：系统名 / 表名 / 接口名 / 工单号 / 服务器名原样保留
7. **不编造**：原始周报未提及的数据**禁止编造**，缺失字段写「未提供」
8. **来源标记**：每条工作必须附 `#src:N`，便于核验
9. **下周计划**：从原始周报「下周计划」字段抽取 + 本周遗留待办合并，不自行推测
10. **风险项**：只列「本周暴露的」风险，不列「理论上可能存在的」风险
11. **跨周闭环**：本周推进或闭环的**上周遗留事项**必须列入「跨周闭环追踪」表
12. **Top 3 亮点**：S 级 + 高价值 A 级中挑 3 条最值得汇报的工作，每条量化
13. **归档前自检**：归档前必须检查
    - frontmatter 字段完整（type/period/period_start/period_end/generated_at/item_count/tags）
    - 文件名日期范围与 frontmatter.period 一致（如 `工作周报_2026-06-29_07-05.md` ↔ `period: 2026-06-29_07-05`）
    - 每条工作都有 `#src:` 标记
    - 5 个维度都存在（无内容的维度写「本周无相关事项」）
    - tags 至少包含：`周报` / `工作总结` / `agent-generated` / 月份 / ISO 周次 / 5 个维度标签
    - 每条工作都有 S/A/B/C 等级前缀
    - C 级条目已合并为汇总行（不是逐条列）
    - S/A/B/C 分布数与正文条目数一致（汇总行已计入）
