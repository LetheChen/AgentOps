# Session Maintenance Protocol（完整决策表）

根文件 `CLAUDE.md` / `AGENTS.md` 顶部嵌入的是**短版**（约 15 行），目的是让 agent 加载根文件时立刻看到自检入口。本文件是**完整决策表**，作为 single source of truth，根文件短版必须与本表锁步。

## 触发条件（满足任一即必须执行）

- ≥ 1 个源文件被改
- 用户新增了约束
- 会话时长 > 10 分钟

## 开始时

1. 读 `TODO.md`
2. 复述当前 🔴 进行中（≤3 项）和 🟡 待处理 段
3. 明确本次会话要推进哪几项

## 结束前（按顺序）

### 1. 回看本次会话实际做了什么

明确列出：
- 改动的文件路径
- 发现的问题（哪些是预期的、哪些是意外的）
- 用户新增的约束（口头的、规则的、隐含的）

### 2. 更新 TODO.md（决策表）

| 本次会话事件 | TODO.md 动作 |
|---|---|
| 完成 🔴 / 🟡 中的某项 | 移到 ✅ 段，附 `(YYYY-MM-DD)` |
| 新发现的 P1/P2 问题 | 加到 🟡 段，附源链接（文件:行号 / issue 编号） |
| 新发现的 P3+ 问题 / 想法 | 加到 🟢 段，附源链接 |
| 主动放弃 / 不再处理某项 | 移到 ✅ 段，备注 `已放弃：<原因>` |
| 无变化 | 不动 ✅ 段（只增不删原则） |

段约束：
- 🔴 ≤ 3 项；超过必须合并或下沉到 🟡
- 🟡 每项必须带 P1/P2 + 源链接
- 🟢 为低优先级 / 想法 / 暂不处理
- ✅ 按日期倒序

### 3. 更新根文件的规则（CLAUDE.md / AGENTS.md）

按本会话暴露的**新约定**对应更新：

| 暴露源 | 更新目标段 |
|---|---|
| 用户反复纠正的行为 | 「Things to avoid」段（追加，不删旧条目） |
| 反复跑错的命令 | 「Verification」段 |
| 团队隐含约定 | 「Project conventions」段 |
| docs/ 目录结构变化 | 「docs/ 目录约定」段 |
| 用户新增的全局规则 | 新增独立段或在最相关段追加 |

### 4. 刷新日期戳

更新根文件顶部 `最后更新：YYYY-MM-DD`，即使其他什么都没变（保持日期戳 = 根文件最近一次审视时间）。

## 与 .claude/rules/ 其他子文件的关系

- `session-maintenance-protocol.md`（本文件）—— 自检决策表，最高优先级，所有 agent 加载
- `root-cheatsheet.md` —— 根文件的速查入口
- `workflow.md` / `harness.md` / `frontend.md` / `knowledge.md` —— 子领域规则，按 paths: 触发加载

## 为什么是「软自动」

无 hook / 无 cron / 无外部触发器。完全依赖 agent 自觉执行本协议。优点：跨所有 agent 客户端、零依赖。代价：上下文拥挤或任务急时可能被跳过。补救：

- 短版块放根文件**顶部**，加载根文件即看到
- 触发条件精简到 3 条（≥1 文件被改 / 用户新增约束 / 会话>10分钟）
- 决策表详细列在本文件，避免短版不足时无据可查
